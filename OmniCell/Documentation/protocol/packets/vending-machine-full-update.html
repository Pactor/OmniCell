The structure is the finding: this message IS a SimpleItemFullUpdate with a tail on it. Its reader calls 0x1009F88A, which calls 0x100A0C87, which calls SimpleItemFullUpdateIIR_t::ReadSubClass at 0x100A1661 and only then reads four more fields. Everything down to the name is that message, field for field, which is why the two share a marker, a pair of stat bytes and a version check. There are three version checks, each abandoning the message on a mismatch: 11 against the static at 0x101C2160 at the front, 2 against 0x101C2084 opening the tail, and 3 against 0x101C1F80 closing it - which accounts for three of the four values previously recorded as an unexplained trailer. The two bytes packed into one short are the same pair SimpleItemFullUpdate carries, written into stat 55 inventoryid and stat 220 currbodylocation by the same code. The trailing Identity list is named now too. It belongs to LockableItemFullUpdate, the class between this one and SimpleItemFullUpdate, and an identity in it may lock and unlock the item: the dispatcher at 0x100A0BEF adds every entry to the LockableItem_t's own list, and 0x10085890 walks that list comparing each entry against whatever is acting on the item, toggling the lock and printing Feedback_YouUnlockedTheItem or Feedback_YouLockedTheItem on a match. The 50 beside it is settled - message + 0x60 is the stat table the message fills in, built at 0x10009D97 as a vector of 1,200 ints seeded with the 1234567890 unset sentinel and indexed by stat id, so byte offset 0x4AC is element 299, lockdifficulty. This message is also where the position rule was decided. The gate is the instance half of the owner identity, not the type: 281 copies carry a position and 281 have a zero instance, while 362 have a zero type, and the 81 that differ settle it - a 143 byte copy with a zero type has no position in it and no room for one, and parsing it the other way puts 0xD8CC0000 where the marker constant has to be. Reading it the wrong way had left thirty seven packets across this message and its relatives unparseable. One correction since: the name's length counts its terminator, which no mission capture could show because every shop in one is unnamed. All 1,354 captured shops now round-trip byte for byte, named and unnamed.
