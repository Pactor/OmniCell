Native client proof: MessageProtocol.dll Message_t::CreateDataBlock creates bytes 2–15; Connection.dll Connection_t::Send at RVA 0x16F3 writes bytes 0–1, 4–7; N3.dll n3InfoItemRemote_t::Write at RVA 0x98F4 writes opcode, affected identity, and ToBePassedOn at bytes 16–28. Retail captures independently match those writes. Packet body: Every byte is identified, and there is one field. Extracted-client BankIIR_t has vtable 0x10161D7C, reader 0x10072518, writer 0x10072537 and dispatcher 0x1007254B. The reader pushes the container and the stream, calls the shared container reader at 0x1002A5DB - the same one FullCharacter's inventory and BankCorpse use - and stops; the writer does the same in reverse. Until 2026-09-11 this class carried an int32 and an Identity after the list as well, and neither is on the wire: they were twelve bytes of our own invention, and the record type beside them called its first int32 ItemFlags and always sent zero, where the shared reader takes that int32 before the record as the placement the entry is filed under. Both are fixed, and the bank now uses the same record as every other container. What makes this the character's own bank rather than somebody else's is the dispatcher: it resolves the message identity to a character and writes that character's own instance into the container's +0x24, where BankCorpse takes an instance off the wire instead. No capture contains one, so BankMatchesTheLayoutTakenFromTheClient pins the layout rather than checking it against retail.
